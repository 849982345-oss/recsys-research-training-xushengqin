# 第四次课：推荐系统入门与公平实验范式

> 本节课从“推荐系统是什么”开始，进一步讲到经典方法、现代方法、真实推荐系统的多阶段结构，以及如何设计公平、可信的推荐实验。
>
> 对零基础同学来说，最重要的不是一次记住所有模型，而是学会用四个问题分析任何推荐论文：
>
>     推荐发生在哪个场景？
>     系统要预测什么？
>     使用了什么数据和方法？
>     实验是否公平、结论是否可靠？

## 1. 本节课的总体框架

1. 推荐系统全景：应用场景、推荐任务、系统阶段；
2. 推荐数据与经典方法：用户、物品、交互、反馈、负采样、UserCF、ItemCF、矩阵分解；
3. 现代方法与真实系统：序列、图、多模态、频域、扩散、生成式检索和大模型推荐；
4. 推荐实验范式：任务定义、数据划分、样本构造、基线、指标和公平比较。

核心观点：

> 一个推荐模型的效果，不只由模型结构决定，也受到数据、任务、切分、负采样、候选集、指标和比较方式影响。

## 2. 搜索和推荐的区别

搜索通常从用户明确输入的查询出发：

    用户输入关键词 → 系统返回相关结果

推荐通常从用户历史行为、物品信息、上下文和群体行为出发：

    用户历史行为 + 物品信息 + 场景信息
    → 系统主动筛选候选内容

搜索更关注用户当前明确表达的需求；推荐可以发现用户还没有明确表达出来的潜在兴趣。现实产品中，搜索和推荐经常结合。

## 3. 推荐系统为什么重要

现实中的商品、视频、音乐、文章和服务数量远超用户主动浏览能力。推荐系统的作用是：

> 帮用户降低选择成本，同时帮助有价值的内容获得曝光。

## 4. 个性化与长尾问题

个性化意味着不同用户看到的候选列表可能不同，而不是所有人都看到同一份热门列表。

物品流行度通常不是平均分布的：

    少量热门物品 → 获得大量曝光和交互
    大量长尾物品 → 很少被发现

如果系统持续推荐热门物品，就会形成反馈循环：热门物品获得更多曝光，产生更多交互，系统又继续推荐它们。这样会压缩长尾物品的曝光机会。

过度个性化也可能造成：

- 兴趣范围越来越窄；
- 用户一直看到相似内容；
- 信息茧房；
- 用户失去探索新内容的机会。

所以推荐系统除了准确率，还要关注覆盖率、多样性、新颖性和长期体验。

## 5. 分析推荐系统的四个维度

| 维度 | 要问的问题 |
|---|---|
| 应用领域 | 推荐发生在哪里？电商、短视频、音乐、新闻、论文还是地点？ |
| 任务形式 | 系统最终预测什么？评分、点击、Top-N 还是下一物品？ |
| 方法路线 | 使用什么信息和模型？内容、协同、序列、图、多模态还是大模型？ |
| 系统阶段 | 方法用于召回、排序还是重排？ |

同一个模型可能被用于不同系统阶段，同一个应用也可能同时使用多种模型。

## 6. 推荐任务

### 评分预测

预测用户会给物品多少分，例如用户 A 对电影 B 的预测评分是 4.5。

### 交互预测

预测用户是否会点击、收藏、购买或播放某个物品。

### Top-N 推荐

从候选物品中形成排序列表：

    用户 A → [物品 7, 物品 2, 物品 9, ...]

### 下一物品预测

根据用户行为序列预测下一次交互：

    历史：[A, B, C] → 预测：D

SASRec 就属于这一类序列推荐任务。

### Session 推荐

只使用当前会话中的行为，不一定依赖长期用户身份。

## 7. 推荐数据的四个基本组成

### 用户

人、账号、设备或匿名会话。

### 物品

商品、视频、音乐、论文、地点、广告或软件服务。

### 交互

浏览、点击、收藏、购买、评分、播放、跳过和停留。

### 上下文

时间、地点、设备、页面入口、当前会话、价格和库存等。

推荐系统可以抽象成：

    用户 + 物品 + 交互 + 上下文
    → 预测用户对物品的偏好或下一步行为

## 8. 显式反馈和隐式反馈

显式反馈是用户明确表达喜欢或不喜欢，例如评分、点赞、点踩和收藏。

隐式反馈是系统从行为中推断偏好，例如曝光、点击、停留、播放、购买和跳过。

隐式反馈容易大量收集，但含义不一定明确：

- 点击可能代表感兴趣，也可能只是误触；
- 没有点击可能是不喜欢，也可能是根本没有看到；
- 购买通常比浏览更强，但也会受价格、库存和场景影响。

重要判断：

> 没有交互不等于明确不喜欢。

## 9. 负采样

隐式反馈通常只记录发生过的行为，没有完整标注负例。训练时常从用户没有交互过的物品中抽取一部分作为负样本。

    正样本：用户真实交互过的物品
    负样本：从未交互物品中采样的物品

但未交互物品不一定真的代表用户不喜欢，可能只是用户没有看到。因此负采样是一种建模假设。

实验必须记录：

- 负样本数量；
- 负样本采样分布；
- 是全量评测还是采样评测；
- 候选集大小；
- 是否过滤用户已经交互过的物品。

## 10. 经典推荐方法

### 流行度推荐

统计全体用户的点击、购买、播放或评分，按热门程度推荐。

优点：简单、不需要用户历史、适合新用户、是重要 baseline。

问题：缺乏个性化、强化热门偏置、压缩长尾曝光。

### 内容推荐

根据用户过去喜欢的物品内容，推荐内容特征相似的新物品。

常用信息包括类别、标签、文本、图片、音频和视频特征。

优点：依据直观、可以利用新物品内容、对物品冷启动有帮助。

问题：依赖特征质量、容易重复推荐相似内容、可能造成兴趣收窄。

### UserCF

    找到与目标用户兴趣相似的用户
    → 汇总邻居喜欢的物品
    → 排除目标用户已经交互过的物品
    → 生成推荐

优点是直观、容易解释、能利用群体协同信号。问题是交互稀疏、用户兴趣变化、新用户冷启动和大规模计算成本。

### ItemCF

    根据共同交互学习物品之间的相似关系
    → 找到用户过去喜欢物品的相似物品
    → 生成推荐

优点是物品关系通常较稳定，容易解释“因为喜欢 A 所以推荐 B”。问题是新物品交互不足、热门共现偏置和推荐结果过窄。

### 矩阵分解

把用户和物品映射到同一个低维空间：

    用户 ID → 用户 Embedding
    物品 ID → 物品 Embedding
    用户向量 · 物品向量 → 偏好分数

矩阵分解是理解现代推荐系统 Embedding 方法的重要基础。

## 11. 现代推荐方法地图

### 序列推荐

研究用户行为顺序和兴趣变化：

    行为序列 → 当前兴趣表示 → 下一物品预测

常见方法包括 RNN、Transformer 和 Self-Attention。

### 图推荐

把用户、物品和交互表示为图：

    用户节点 — 交互边 — 物品节点

图模型可以利用用户—物品、物品—物品、用户—用户以及高阶关系。

### 多模态推荐

同时使用文本、图片、音频、视频和用户行为。重点不是模态越多越好，而是判断模态是否有用、是否冲突、是否缺失、是否含噪声以及是否增加成本。

### 自监督和对比学习

在标签不足时，利用数据自身构造辅助信号，例如数据增强、相似表示拉近和不相关表示拉远。

### 频域推荐

    行为序列
    → 从时间域转换到频域
    → 分析不同频率成分
    → 过滤噪声或学习周期行为
    → 预测下一物品

课程提到 FMLP-Rec 和 FEARec。频率成分的推荐含义不一定直观，必须通过实验验证。

### 扩散推荐

    用户偏好或物品表示
    → 逐步加噪
    → 学习逐步去噪
    → 恢复偏好或目标物品表示

课程提到 DiffRec 和 DiffuRec。多步去噪会增加训练和推理成本，噪声过程和步数也会影响结果。

### 生成式检索

传统召回是用户向量到物品向量库中做近邻搜索；生成式检索尝试根据用户历史直接生成目标物品的语义 ID。

课程提到 TIGER。关键问题包括语义 ID 设计、目录更新、生成错误和推理效率。

### 语言模型推荐

P5 把用户、物品、交互和任务指令转换为文本序列，用统一语言建模目标处理推荐列表、评分预测、解释和评论生成。

注意：

> P5 是把推荐任务语言模型化，不等于通用聊天大模型已经可以直接替代完整推荐系统。

### 大模型增强推荐

大模型可以：

1. 直接生成推荐、解释或对话；
2. 用推荐数据微调后成为推荐模型；
3. 提取物品属性、用户画像和关系信息，作为特征增强器。

课程提到 P5、TALLRec 和 LLMRec。主要问题包括成本、时延、幻觉、物品落地约束、隐私和评估困难。

## 12. 真实推荐系统的多阶段结构

真实系统通常不是一个模型直接从海量物品生成最终列表：

    海量物品
    → 召回：快速筛选候选
    → 排序：精细预测相关性
    → 重排：加入多样性、规则和安全约束
    → 最终推荐列表

召回关注速度和覆盖，排序关注相关性，重排关注多样性、新颖性、业务规则、安全和重复控制。

论文可能只研究一个任务、一个模型和一个系统阶段；真实系统通常包含多路召回、多个排序模型、重排规则、实时数据、延迟约束和安全治理。因此离线指标提升不等于完整线上系统一定变好。

## 13. 推荐系统合规和安全

推荐系统会处理用户行为、兴趣和个人信息，需要关注：

- 数据是否有合法处理依据；
- 是否只收集实现目的所必需的数据；
- 是否清楚告知个性化推荐；
- 是否提供关闭或拒绝个性化推荐的方式；
- 用户是否可以修改或删除推荐标签；
- 是否存在暗中追踪或超出原目的使用；
- 是否向未成年人推荐有害内容；
- 是否操纵榜单、热搜或制造虚假互动；
- 是否存在不合理差别定价；
- 是否允许用户申诉并获得必要说明。

这些问题应贯穿数据、目标、特征、评测和上线环节。

## 14. 推荐实验标准流程

    明确任务
    → 选择数据
    → 说明数据处理
    → 划分数据
    → 构造样本
    → 选择 baseline
    → 统一训练和评测
    → 分析指标
    → 写清结论边界

### 明确任务

先说明最终预测什么：评分、交互、Top-N、下一物品或 Session。

### 说明数据

至少记录用户数、物品数、交互数、交互类型、时间范围、稀疏程度、过滤规则和数据版本。

### 划分数据

- 训练集：学习模型参数；
- 验证集：选择模型和调参数；
- 测试集：最后一次评估。

序列推荐通常按时间划分：

    过去行为 → 训练
    较新行为 → 验证
    最后行为 → 测试

### 避免时间泄漏

错误做法：

- 随机打散完整行为序列；
- 让未来点击进入训练集；
- 使用未来统计量预测过去；
- 让测试信息参与特征构造。

正确原则：

> 数据划分必须与真实预测场景一致。

### 选择公平 baseline

建议从简单到复杂：

    流行度推荐 → ItemCF → 矩阵分解 → 现代模型 → 当前方法

公平比较尽量保持一致：

- 数据版本；
- 预处理；
- 数据切分；
- 负采样；
- 候选集；
- K 值；
- 训练预算；
- 调参条件；
- 指标定义。

### 选择指标

除了准确性，还要根据任务关注覆盖率、多样性、新颖性、用户满意度、效率、鲁棒性、公平性和校准。

## 15. 如何判断实验结论是否过度

一次实验最多支持这样的结论：

> 在当前数据集、任务定义、数据划分、负采样、候选集和指标设置下，模型 A 的 NDCG@10 高于模型 B。

不能直接推断：

- 模型 A 在所有数据集上都更好；
- 准确率提高就代表多样性和效率也提高；
- 离线指标提高就代表线上体验提高；
- 复杂模型一定比简单 baseline 更有价值；
- 当前数据上的结果就是通用规律。

论文和实验记录必须写清楚适用范围和限制。

## 17. 本节课最重要的五句话

1. 推荐系统不是单一模型，而是数据、任务、方法、系统阶段和评测组成的系统。
2. 没有交互不等于用户不喜欢，负样本通常包含建模假设。
3. 论文结果能否比较，取决于数据、切分、候选集、负采样、指标和训练条件是否一致。
4. 离线指标提升不等于线上体验、效率、多样性和安全一定提升。
5. 新手应先学会分析任务和实验，再追逐复杂模型和最新名词。
